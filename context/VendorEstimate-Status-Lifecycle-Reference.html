1. Overview & Two Edit Paths

A Vendor Estimate is stored as one header row in VendorEstimate plus line items in:

  • VendorEstimateDetail — materials / trip charges (non-labor)
  • VendorEstimateDetail1 — labor hours

Status lives in VendorEstimate.Status (int). Display labels are derived in ManageVendorInvoice.GetVendorEstimateList.

⚠️ Two parallel edit UIs exist:
  • Current (Job Main Tab): MdtVendorEstimateNew → CreateEstimate / EditEstimate wizard. This is what admins use day-to-day.
  • Legacy: MgtVendorEstimateController.Edit + ManageVendorEstimates.SaveEstimateForEdit. Same tables, older form; still referenced by some redirects to DetailVendorEstimate.
  • Status dropdown screen: MgtVendorInvoice/UpdateVendorEstimate — the authoritative place to manually set Status 0/1/2/3/4/5 via SaveVendorEstimate.

Canonical mapping from ManageVendorInvoice.GetVendorEstimateList (line ~229):

At submit, SaveVendorEstimate does model.Status = Convert.ToInt32(inv.ItemName). The dropdown Value is the Status code. IsApproved / IsCancelled / IsNew are set separately per branch.

6.1 Edit save first resets to Status 5

SaveEditNewEstimate (and legacy SaveEstimateForEdit) always:

  1. Archives to VendorEstimateArchive + VendorEstimateArchiveDetail
  2. Sets header: Status=5, IsApproved=false, IsNew=true, IsSeen=false, IsEdited=true
  3. Upserts detail rows (new rows get NewLineAddedAfterEdit = "Change Order Item")
  4. Writes “Edit Estimate” note

Then the button branch immediately moves Status to 2 or 1.

7. Status 1 — Estimate Approved

Meaning: This is the live approved estimate for the vendor on the job. Only one should remain “live”; siblings are declined.

7.A Wizard path — SetEstimateToApproved

GET /MdtVendorEstimateNew/SetEstimateToApproved?EstimateKey={guid}

Writes / updates:

Table / fieldChange
VendorEstimate Status=1, IsApproved=true, IsCancelled=false, IsNew=false, MutiEstiIdentifier=InvoiceKey, MCEstimate bumped, OtherRemark="Approved => … APPROVED VENDOR ESTIMATE.", ApprovedBy=login name, OtherDate=UtcNow
VendorEstimateDetail / Detail1 (active)ApprovedByCustomer = 1
Sibling VendorEstimate same Job+VendorStatus=3, IsApproved=false, remark declined-by-approval, MutiEstiIdentifier=approved key
JobVendor.RevVendorDNE= sum of estimate (VendorHelper.GetVendorEstimateTotal)
Job.RevVendorDNEMirrored if this JobVendor IsDefault
Notes (RCSmessaging)“Vendor estimate … has been approved…”
CancelAllRegardingVendorEstimates(..., formoption=1) Deletes JobActionNeeded ActionID ∈ {50, 61}; clears highlight factor 8 / EstimateResponse flags

Return flag to UI:

  • 1 — job status trigger is NOT 4 or 17 → show full Additional Approval panel (all options)
  • 2 — job already checkout-adjacent → pre-select checkout radio (#2) + call WhenCheckoutIsSelected()
  • 0 — error message shown inline

UI next Not a Bootstrap modal — an inline panel #frmAdditionalApprovalToVendor is shown (see §14).

7.B Manual path — UpdateVendorEstimate ItemName="1"

ManageVendorInvoice.SaveVendorEstimate when inv.ItemName == "1":

  • Same approval + sibling decline + RevVendorDNE + CancelAll (formoption 1)
  • Writes JobStatusHistory via UpdateVendorEstimateJobStatusHistoryAsync (“Estimate Approved” / “Quote Approved” / “Received Additional Approval” by job stage)
  • Vendor deposit side-effect: if VendorDepositSet exists and no deposit JobBill yet → AccountingHelper.SaveVendorBills creates deposit bill
  • If OnsiteApproval==true → admin→vendor message “Proceed with Repairs…”
  • Redirect → DetailVendorEstimate/{MutiEstiIdentifier}

7.C Main Job Tab quick-approve

  • GET /MgtJob/SetTheEstimateApproved?EstimateKey&NewEstimateAmt&NewApprovalRemarks — Status=1 + note; does not update RevVendorDNE or cancel siblings
  • GET /MgtJob/SetTheEstimateApprovedForOption1 — same without amount/remarks

Used from JobMainTabSave.js with an approval-progress message modal area (#msgForEstApprovalModal).

7.D Auto-approval from customer estimate

See §19 — sets Status=1 when customer estimate is approved and 80% / EditedByVendor / toggle rules pass.

8. Status 2 — Pending Approval

Meaning: Waiting on customer (or admin standing in for customer). Not yet an approved DNE.

How you get here

PathWhat happens
Wizard “Send to Customer” SetEstimateToVendingApproval: Status=2, IsApproved=false, IsNew=false, OtherRemark pending text, detail ApprovedByCustomer=1, siblings → Status=3, CancelAll formoption=2, note written, then redirect to customer-estimate CreateNew

9. Status 0 — Estimate Reject / Resubmit

Meaning: Admin rejected with instructions to revise. IsCancelled = true (unusual — cancelled flag used here, not for Status=3).

Only from SaveVendorEstimate when ItemName == "0":

  1. OtherRemark = “Rejected for resubmission::” + AdminRemark
  2. IsApproved=false, IsCancelled=true, IsNew=false, Status=0
  3. JobStatusKey → GlobalClass.GetJobStatus(8) on Job (if default vendor) and JobVendor
  4. CancelAll formoption=1
  5. Note with inline estimate HTML
  6. Emails vendor via SendEditVendorEstimateMailToVendor(InvoiceKey, VendorKey, AdminRemark)
  7. JobStatusHistory: “Rejected for resubmission” (or Quote/Onsite variants)

UI No special modal beyond the status dropdown + AdminRemark CKEditor on UpdateVendorEstimate.

10. Status 3 — Not Approved / Declined

Meaning: Dead path for this estimate. Displayed as red “DECLINED” banner in InvoiceCreator.

Entry paths

PathSide effects
UpdateVendorEstimate ItemName="3" Multi-choice shuffle if MCEstimate==1 (re-point MutiEstiIdentifier to another sibling).
CancelAll(1). Thank-you decline email to vendor if no other live estimates remain.
JobStatusHistory “Estimate Declined”.
Approving another estimate (wizard or SaveVendorEstimate "1") Siblings auto Status=3 with decline remark — no thank-you email per sibling
Vendor unassigned UnwindTheEstimateForDeletedVendor: estimates where Status∈{2,99} → Status=3, remark “vendor has been unassigned”, CancelAll(1), note. Modal on CreateVendor: warn if pending estimates exist before unassign.

Optional follow-up: Admin can create a vendor invoice from incurred lines only → sets CreatedInvoiceForIncurredAfterDeclined = true on the declined VE (invoice tables written separately).

11. Status 4 — Submitted / Pending Review

Initial state after wizard create (or manual set). Flags: IsApproved=false, IsCancelled=false, IsNew typically true on create.

From UpdateVendorEstimate ItemName="4": updates remark + CancelAll(2) + JobStatusHistory “pending review” — keeps it waiting for admin review without approving.

12. Status 5 — Change Order Request / Pending Review

Triggered whenever an existing estimate is edited/saved:

  • SaveEditNewEstimate
  • Legacy SaveEstimateForEdit (also sets Job/JobVendor JobStatusKey via GetJobStatus(9) — change-order-ish job status)
  • Legacy line-item add/delete on MgtVendorEstimateController.Edit POST
  • Manual Status=5 from UpdateVendorEstimate

UI display: InvoiceCreator wraps Status==5 in alert-changeorder styling.

Archive first: every meaningful edit calls SaveVendorEstimateOriginalVersion → snapshot into:

  • VendorEstimateArchive (Version = count+1, OriginalInvoiceKey = live key)
  • VendorEstimateArchiveDetail (materials + labor flattened)

19. Customer-Estimate Auto-Approval of Vendor Estimate

When admin/customer approves a JobSalesInvoice estimate that is linked to vendor estimate(s):

  1. Customer.ToggleApproveVendorEstimate must be true
  2. Link via JobSalesOrderToVEstimate OR JobSalesInvoice.VendoeEstimateKey
  3. 80% rule: vendor total < 80% of approved customer amount
  4. EditedByVendor must be null
  5. Status != 3

On success: VendorEstimate Status=1, RevVendorDNE updated, CancelAll siblings, note logged.
Source: UtilityTasks.cs (customer approve path). Full detail in repo docs Vendor-Auto-Approval-Logic.md.

20. Gotchas & Non-Obvious Rules

  • Editing always un-approves. SaveEdit → Status=5 before any re-approve/pending step. Never leave an edited estimate at Status=1.
  • Soft vs hard delete. New wizard soft-deletes (MarkNotNeededCmt). Legacy controller hard-deletes rows.
  • IsCancelled=true only on Status 0, not on Status 3.
  • Only one live estimate per Job+Vendor when approving — siblings forced to Status=3.
  • CancelAllRegardingVendorEstimates does NOT cancel estimate rows; it clears ActionNeeded {50,61} + highlight flags. Sibling Status=3 is a separate loop.
  • Option 5 hidden field is "55" but client branch checks radio value "5".
  • 65% (wizard approve) is soft warn; 80% (UpdateVendorEstimate / auto-approve) is hard block / fail auto-approve. Different thresholds!
  • No ambient DB transaction. Each step saves independently — partial failure can leave Status mid-lifecycle.
  • Job status trigger 9 on legacy edit = change-order-related job status; new wizard relies more on Status=5 on the estimate itself.
  • Detail ApprovedByCustomer=1 is set even when Status=2 (“send to customer”) — name is misleading; it marks lines as selected for the flow.
  • GetEstimateForEdit sets model.Status=99 for the legacy view model only — may not persist to DB until save.

1. Overview

Quick Job is a streamlined job creation screen that lets an admin:

  • Create a job with customer, location, trade, priority, description, and DNE values
  • Optionally attach files before save (staged in TempFileStock)
  • Optionally assign a vendor immediately and send a work order
  • Optionally broadcast to multiple vendors
  • Optionally duplicate the job to additional locations (up to 15)
  • Handle upline approval, primary vendor rules, and customer acknowledgment emails

Entry point: GET /MgtJob/CreateQuickJob

Submit: POST /MgtJob/CreateQuickJob with JobClass model + extra form parameters

9. File Upload Flow

  1. User selects DocumentType + optional FileName label
  2. Dropzone POSTs to MgtJob/UploadFiles?id={PersonnelKey}
  3. Each file → TempFileStock row keyed by PersonnelKey
  4. DataTable loads via GetTempAttachedFilesForQuickJob
  5. On job save: TempFileStock rows moved to JobFile via JobFileSetup.SaveAttachmentInJobFile
  6. Images are resized (max ~600x800) before storage
  7. Duplicate titles get numeric prefix via ResolveDuplicateFileName

10. Vendor Assignment Paths — withoutVendor Values

ValueUser ActionPost-Save Behavior
"0" No vendor / upline bypass submit Job only → redirect EditJob
"1" "Add vendor and send work order now" OR Save with vendor selected CreateDefaultVendorWorkOrder → vendor + work order + email → EditJob
"2" "Search vendor now" Redirect MgtJobVendor/CreateVendor/{JobKey}
"3" "Save job and add vendor later" Job only → redirect EditJob
"4" "Save job and broadcast work order" Redirect MgtJobBroadcast/Index/{JobKey}?id1={SendToallVendor}&id2=2
"33" "Dispatch" on primary vendor modal (all locations have primary) Auto-dispatch to primary vendor

CreateDefaultVendorWorkOrder sequence

  1. JobVendorConfiguration.SaveVendorForQuickJob
  2. JobWorkOrderConfigSetup.SaveWorkOrderAndReturnWorOrderObject
  3. MailToVendor.SendWorkOrderToVendors — email template ID 3
  4. Update JobWorkOrder.SentDate, EmailSent=true
  5. Set JobVendor.JobStatusKey = GetJobStatus(2) — "sent to vendor" status
  6. If IsDefault: sync Job.JobStatusKey to vendor status
  7. Save action needed (ActionID 91)

11. Post-Save Branching Logic

POST CreateQuickJob │ ├─ ModelState invalid → re-render form with ViewBag dropdowns │ └─ SaveMainData success (flag=1) │ ├─ Move TempFileStock → JobFile │ ├─ Duplicate to MultipleLocationKey[] (if any) │ └─ per location: new Job + copy files + notes + upline emails │ └─ Check LocationTradeServiceRequestUpline (LocationKey + TradeKey OR AllTrade GUID) │ ├─ UPLINE EXISTS + not Emergency + UplineBearer=0 │ ├─ Expirydate IS NULL → SendApprovalEmailToCustomerLandLord → EditJob (STOP) │ ├─ Expirydate < today → acknowledgment email + vendor path │ └─ Expirydate valid → SendApprovalEmailToCustomerLandLord → EditJob (STOP) │ └─ NO UPLINE (or emergency override) ├─ SendJobCreateAcknowledgmentToCustomer └─ Branch on PrimaryVendor + withoutVendor (see section 10) ├─ PrimaryVendor=1 + multiple primary vendors → MgtAssignPrimaryVendor/Index ├─ withoutVendor=1 → vendor + work order ├─ withoutVendor=2 → MgtJobVendor/CreateVendor ├─ withoutVendor=4 → MgtJobBroadcast/Index └─ else → EditJob

Upline check details

  • Table: LocationTradeServiceRequestUpline
  • Match: LocationKey AND (TradeKey OR AllTrade 287EEC8C-84CB-42AF-B8A1-00A676E64D0B)
  • UplineBearer = Customer.EmergencyUplineOverride (true → 1, bypasses upline for emergencies)
  • Emergency job type bypasses upline: fc078fd5-5ddc-4088-8a9f-d982436e20fd

Primary vendor check (CheckForPrimaryVendorQuickJob)

Lookup order: PrimaryVendorTradeState → PrimaryVendorTradeCity → PrimaryVendorTradeZipcode

Returns flag=1 if a different primary vendor exists for trade+location.

  2. INSERT activity note ("New Job")
  3. INSERT JobAdditionalTrade (if additional trades)

  5. INSERT JobFile from staged temp files
  6. INSERT duplicate Jobs + files + notes (if applicable)

  9. Send work order email (if assign_and_send)
  10. Update job/vendor statuses after work order send

Business rules to preserve exactly

  • VendorDNE = 0 for Bid Request and Special Project job types
  • PO auto-generated from SQL sequence when empty
  • JobName auto-generated from location name + date when empty
  • JobName uniqueness check before submit
  • Description minimum content length (~26 chars of HTML)
  • Primary vendor warning when selected vendor ≠ configured primary
  • Upline approval blocks dispatch (redirect to EditJob after approval email)
  • Emergency + UplineBearer bypasses upline modal
  • Broadcast only for PriviledgedForVendorBlast customers
  • Max 15 duplicate locations per save
  • Temp files keyed by user PersonnelKey until job created
  • CheckInExpiryTimeInMinutes from CustomerDetailFactor or default 15
  • Vendor rates set via VendorHelper.SetVendorRates with AllTrade fallback

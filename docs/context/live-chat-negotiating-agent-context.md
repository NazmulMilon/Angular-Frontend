- Live Chat styles (local) → `src/app/features/live-chat/live-chat-widget.component.scss`

**State — Reads:**

- Selected thread's `currentEstimate.estimateKey`
- Existing estimate turn actions from `ThreadEstimateDto.allowedActions`
- Negotiation DTO contracts from `src/app/models/vendor-bills.model.ts`

**State — Writes:**

- Main pane tab (`chat` / `negotiate`)
- Negotiation loading, error, submission, line-decision, and edited-value state
- Current estimate refresh after a counter is delivered

**API Calls:**

- `pollNegotiationUntilReady()` → `src/app/services/negotiating-agent.service.ts` — GETs `/api/v1/admin/vendor-bills/estimates/{estimateKey}/negotiation` until recommendations are ready.
- `acceptAll()` → `src/app/services/negotiating-agent.service.ts` — POSTs notes to `/accept-all`; backend builds all recommended actions and delivers the counter.
- `sendCounter()` → `src/app/services/negotiating-agent.service.ts` — POSTs round number, per-line actions, values/qty, and notes to `/send-counter`.
- `loadThreadEstimate()` → `src/app/features/live-chat/job-chat-estimate.service.ts` — refreshes estimate status, turn permissions, and rendered estimate after delivery.

**Navigation:**

- Chat tab → existing chat message pane.
- Negotiate tab → negotiating-agent panel for the selected estimate.
- Changing or closing a thread resets negotiation state.

**Side Effects:**

- Negotiation endpoint can create/sync an agent proposal on first load.
- Sending a counter updates the same estimate, archives its prior version, posts delivery to the agent, and notifies the vendor through backend delivery services.
- Polling uses timers in `NegotiatingAgentService`.

**Business Logic:**

- Panel is available only when the estimate turn allows `negotiate`.
- Lines with `counterThisLine=false` pass through unchanged.
- Accept uses the agent suggestion; Edit uses the admin-entered value; Decline sends the existing decline action contract.
- Vendor permissions remain backend-controlled; UI labels must not infer permissions.
